总结：

冰蝎主要有四大版本

冰蝎1.0

早期版本加密能力弱，流量特征明显，在目前显示环境中基本无使用。

冰蝎2.0

其主要特点是:动态密钥协商 + AES 加密通信 + HTTP 隧道化控制。攻击者与webshell之间的命令加密传输不再是明文传输。

冰蝎2.0通信流程分为密钥协商和加密通信两个阶段。首先，客户端首次连接 WebShell 时，服务端会生成随机密钥并返回给客户端，双方完成密钥交换；随后，客户端和 WebShell 使用该密钥进行 AES 加密通信，所有执行命令、文件操作等数据都会经过加密后通过 HTTP 请求传输，服务端解密后执行并将结果加密返回，从而隐藏真实通信内容。

冰蝎3.0

冰蝎3.0相比2.0最大的变化是取消了动态密钥协商过程，改为预共享密钥进行加密通信。

冰蝎3.0通信过程主要依靠预共享密钥进行加密传输。客户端与 WebShell 在通信前已经约定好连接密码，客户端会通过对密码进行 MD5 运算并截取指定长度生成 AES 加密密钥，之后所有的数据交互都会使用该密钥进行 AES 加密。客户端将执行命令、文件操作等数据加密后通过 HTTP POST 请求发送给 WebShell，WebShell 接收到请求后使用相同密钥进行解密，执行相应操作，并将执行结果再次加密返回给客户端。相比冰蝎2.0，3.0取消了首次连接时的密钥交换过程，避免了通信初期密钥暴露的问题，提高了隐蔽性。

所以相较于bx2.0，我们对他的检测从找密钥协商的握手流量变为分析特征行为。

冰蝎4.0

冰蝎4.0相比3.0最大的变化是：通信协议更加模块化、可配置化，弱化了固定流量指纹。因此分析冰蝎4.0时，不能像3.0一样主要依赖固定 Key、固定 Header，而要更多关注协议行为、加密方式、流量形态和 WebShell 特征。

强特征：

  1. 相较于bx3.0的aes加密，bx4.0可以自定义加密协议

因此：

  • 不再完全依赖默认 AES 特征
  • 不同配置可能产生不同流量

  1. 与3.0一样POST body含有大量随机数据

  2. 固定协议头特征

    冰蝎4.0部分版本在通信数据中存在固定协议标识，该特征位于加密数据之前，与具体选择的加密算法关系较小。
