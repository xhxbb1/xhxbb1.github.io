常见杀软特点总结

杀软一般通过以下几点来检测恶意软件和行为：

  1. 静态查杀：最基本的查杀方式，主要通过对文件的特征码进行扫描，匹配已知的病毒特征库。如果发现文件特征码与病毒特征库中的某个病毒特征码相匹配，就判断该文件为病毒；部分杀软会在静态查杀时将程序放入沙箱中运行几秒的方式以检测程序是否是恶意程序。

  2. 动态（主动）查杀：通过在程序运行时扫描程序内存是否匹配病毒特征的方式主动发现恶意程序。在EDR中还会挂钩敏感的Windows API，在程序调用到被挂钩的API时检查函数参数和调用栈以检测恶意程序。

  3. 流量监控：监控网络流量，分析网络数据包，如果发现异常流量或者已知的恶意流量特征，就可能是恶意软件在进行网络活动。

  4. 行为监控：监控程序的运行行为，如文件操作、注册表操作等。如果发现某个程序的行为超出了正常范围，就可能是恶意软件。

常见杀软特点

  • 火绒：静态查杀能力弱，没有动态查杀，横向移动防护比较强，frp等内网穿透受影响。

  • 360安全卫士/360杀毒：静态查杀能力较强，没有动态查杀，如果开启了核晶模式，则行为查杀比较强，注入进程等敏感行为会被拦截；核晶模式在物理机中默认开启，在虚拟机中默认关闭。

  • 360QVM：360QVM 简单的说就是使用了机器学习辅助查杀，在360杀毒引擎设置中开启 360QVM 后静态查杀会变得非常流氓，有一点特征就会被查杀。

  • Windows Defender：静态查杀能力较强，动态查杀较强，监控 HTTP 流量。

  • 卡巴斯基：普通版静态查杀能力一般，企业版静态查杀能力较强，动态查杀较强。

  • ESET：静态查杀能力较强，没有动态查杀。

按照静态查杀能力强弱排列

火绒 < 360安全卫士、360杀毒、Windows Defender、卡巴斯基标准版 < 卡巴斯基企业版、ESET < 360QVM。

目前见过静态查杀能力最强的属360QVM，连国外的杀软都有所不及，可以说360QVM是非常流氓的了。

按照动态查杀能力强弱排列

火绒、360、ESET < 卡巴斯基 < Windows Defender。

火绒、360、ESET 这几个没有动态查杀。

一些概念

C2（Command and Control）

C2（Command and Control，命令与控制）指攻击者与被控主机之间建立的通信控制方式。

在攻击者获取目标主机权限后，需要通过 C2 通道向目标发送命令，并接收执行结果，从而实现对目标主机的远程控制。

简单来说，C2 就像攻击者与目标机器之间的“遥控通道”。

常见 C2 框架：

  • Cobalt Strike：目前红队中使用较多的商业化 C2 平台。
  • Metasploit：集成 Meterpreter，可以建立远程控制会话。
  • Sliver：开源 C2 框架。
  • Mythic：模块化开源 C2 平台。
  • Empire：基于 PowerShell 的 C2 框架。

除此之外，冰蝎、哥斯拉、蚁剑等 WebShell 管理工具也可以看作一种 Web C2，通过 WebShell 实现对目标服务器的控制。

常见 C2 通信方式包括：

  • HTTP/HTTPS
  • TCP
  • DNS

C2 是红队攻击链中的重要组成部分，负责维持攻击者与目标之间的持续通信。

什么是 ShellCode

ShellCode 是一段用于实现攻击目的的机器指令代码，通常以二进制形式存在，攻击者会将其注入到目标进程中执行。

早期 ShellCode 主要用于获取 Shell（命令行控制权限），因此得名 ShellCode。随着攻击技术的发展，ShellCode 的功能已经不局限于获取 Shell，还可以用于执行命令、加载木马、建立 C2 通信、权限提升等操作。

简单来说，ShellCode 就是一段能够在目标机器上执行特定功能的代码，是漏洞利用中的重要组成部分。

常见用途：

  • 获取远程 Shell
  • 执行任意命令
  • 下载并执行 Payload
  • 加载 C2 Agent
  • 权限提升

在漏洞利用流程中，通常为：

漏洞触发 → 执行 ShellCode → 获取控制权限 → 建立 C2 通信

ShellCode 通常具有体积小、无文件落地、直接在内存中执行等特点，因此经常被用于漏洞利用和免杀技术研究中。

什么是机器码

机器码（Machine Code）是计算机 CPU 能够直接识别和执行的二进制指令，是程序在计算机底层运行的最基本形式。 程序员编写的代码（如 C、C++、Java 等）需要经过编译或解释，最终转换为机器码，CPU 才能执行。

什么是 ShellCode Loader

ShellCode Loader（ShellCode 加载器）是一种用于加载并执行 ShellCode 的程序。

它的主要作用是将 ShellCode 加载到内存中，并通过一定方式触发执行。由于 ShellCode 通常是一段原始机器码，无法像普通程序一样直接运行，因此需要 Loader 负责解析、加载和执行。

简单来说：

ShellCode Loader 就是一个“启动器”，负责把 ShellCode 送入内存并让 CPU 执行。

基本流程：

ShellCode
↓
Loader读取
↓
申请内存空间
↓
写入ShellCode
↓
修改执行权限
↓
调用执行

常见功能：

  • 读取 ShellCode
  • 内存分配
  • 加载 ShellCode
  • 执行 ShellCode
  • 对 ShellCode 进行加密或解密

在安全研究中，ShellCode Loader 常用于漏洞利用、红队工具开发和恶意样本分析中。

例如：

攻击者可能将 ShellCode 进行加密保存，然后通过 Loader 在运行时解密并加载到内存执行，以减少静态检测特征。
